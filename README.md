# new-soxl-soxs-bot

SOXX 레짐 분류 기반 SOXL/SOXS 전략. 백테스트, 신호 생성, **토스증권 Open API 자동매매**까지
구현돼 있습니다.

⚠️ **실제 주문은 `--live` 를 명시할 때만 나갑니다.** 기본 실행은 읽기 전용이고,
`--execute` 는 안전장치 전부를 검사한 뒤 드라이런만 합니다.
주문을 즉시 멈추려면 `config/HALT` 파일을 만드세요(킬 스위치).

**API 실검증 현황** (2026-09-22, 실계좌): 조회 전부와 주문 생성·체결 확인이 통과했습니다
(프리장에서 SOXS 1주 지정가 매도 → FILLED). 다만 **전략 매수가 쓰는 금액 주문
(`orderAmount`)과 SWITCH의 매도→매수 연속 자금은 아직 미검증**입니다. 첫 실거래는
금액을 제한해서 시작하십시오(`--capital 500 --min-capital 0`).

## 전략 한 줄 요약

SOXX **50일선 + 20일 기울기 + 가격 20일 변화**로 장세를 셋으로 나누고, 레짐마다 다른
규칙을 씁니다. 상승/하락은 **세 조건을 모두** 만족해야 하고, 하나라도 엇갈리면 횡보입니다.

가격 조건을 넣은 이유: 이동평균 기울기는 가격보다 늦게 돕니다. 급락이 50일 창에 남아
있으면 가격이 평평해져도 선은 계속 내려가서, 실제로는 횡보인 구간이 "하락"으로
분류됐습니다(2026년 8월이 그 예 — SOXX가 507→511로 평평했는데 35일 중 25일이 하락).
전체 기간으로도 "하락" 라벨의 48%가 오르면서 끝나고 있었습니다. 가격 조건을 더하니
상승 레짐 거래 승률이 **31.4% → 54.9%** 로 올랐습니다([docs/STRATEGY.md](docs/STRATEGY.md) 3.1).
z는 **14일 볼린저** 기준입니다(`z = (종가 - 14일 중심선) / 14일 표준편차`).

**"밴드"는 z = ±2.0을 가리키는 관례적 명칭입니다.** 코드는 밴드 선을 계산하지 않고
z만 씁니다(`Params.bb_std`는 선언만 돼 있고 어디에서도 쓰이지 않으며, 실제 밴드를 긋는
`indicators.bollinger_bands()`는 호출되지 않는 죽은 코드입니다). 진입 z≤-1.7은 하단
밴드까지 85% 지점이며, **횡보에는 z 기반 익절 목표가 없습니다**(아래 참고).

| 레짐 | 진입 | 청산 |
|---|---|---|
| 상승 | SOXL 즉시 매수 | 레짐 이탈 또는 고점 대비 -25% |
| 횡보 | z≤-1.7 → SOXL / z≥+1.7 → SOXS | 레짐 이탈 / **중심선 z=0 복귀** / 반등 후 꺾임 / 10일 |
| 하락 | z≤**-2.0** → **SOXL** (반등 매수) | 레짐 이탈 / z가 0 복귀 / 반등 후 꺾임 / 5일 |

**고정 % 익절·손절은 쓰지 않습니다.** 횡보·하락 모두 진입 근거가 사라지는 지점에서만 나옵니다.
**반등 후 꺾임**은 SOXX 5일선 기울기가 포지션에 유리한 방향으로 돌아섰다가(반등) 다시
반대로 꺾일 때입니다. 밴드 이탈 진입은 정의상 단기 추세를 거스르므로, 반등이 확인되기
전에는 청산을 무장하지 않습니다. 하루 반전이 아니라 기울기를 쓰는 것은 종가 한 번 밀린
것을 "추세가 꺾였다"로 읽지 않기 위해서입니다.

**횡보 익절은 중심선(z=0)입니다.** 반대편 밴드(±1.5, ±1.0, ±0.8)를 목표로 두면 횡보
레짐(평균 12거래일) 안에 도달하지 못해 실측 발동이 0~2건이었습니다. 중심선은 실제로
발동합니다(최근 3년 횡보 16건 중 6건). 파라미터 탐색에서 **학습·검증 구간이 둘 다
개선된 유일한 선택지**였습니다([docs/STRATEGY.md](docs/STRATEGY.md) 6.4).

진입 z는 **1.65~1.90이 안정 구간**입니다(검증 36~43배, 그 밖은 24~26배). 1.7은 그
안에 있습니다. 타임스톱(10/15/20)과 볼린저·단기선 기간은 차이가 잡음 수준이라
바꾸지 않았습니다.

**하락장에 SOXS를 쓰지 않습니다.** 세 번 검증했고 모두 실패했습니다([docs/STRATEGY.md](docs/STRATEGY.md) 4.1).

## 자본 규칙

매수 금액 = **max(현재 자산, $5,000) × 노출**.

- 이익이 나면 그대로 복리로 굴립니다.
- 자산이 **$5,000 아래로 떨어지면 그만큼 새로 입금해 채워** 매수합니다.

```
자산 $12,000 → 매수 $12,000   추가입금 $0
자산  $1,200 → 매수  $5,000   추가입금 $3,800
```

⚠️ **이건 낙폭에 물타기입니다.** 하락 후 회복하면 크게 보상받고, 회복하지 않으면 손실이
커집니다. 그리고 추가입금이 있으면 "최초 원금 대비 몇 배"는 성과가 아니므로, 백테스트가
**총 투입(최초 원금 + 누적 추가입금) 대비**로 보고합니다.

실측: 대부분 구간은 추가입금이 0입니다(자산이 일찍 $5,000 위로 올라가면 이후 낙폭이
-90%여도 절대금액이 커서 하한에 닿지 않습니다). **최근 5년만 크게 달라집니다** —
2021~22년 하락에서 $5,782를 추가 입금했고, 그 커진 원금이 2023년 이후 랠리를 타서
최종 자산이 $85,350 → $319,695가 됐습니다(투입대비 29.65배).

입금은 **자동이 아닙니다.** 계좌에 돈이 없으면 `USD 매수 가능 금액이 부족합니다` 로
주문이 막히고, 직접 입금하셔야 합니다. 하한을 끄려면 `--min-capital 0`.

## 백테스트 (원금 $5,000, 노출 100%, 왕복비용 0.2%)

| 구간 | 전략 | MDD | Sharpe | 거래 | 승률 | 세후 | SOXL 보유(세후) | SOXX 보유(세후) |
|---|---|---|---|---|---|---|---|---|
| **최근 3년** | **33.25배** | **-52.0%** | **1.70** | 36건 | **66.7%** | **22.45배** | 8.13배 (6.64) | 3.68배 (3.17) |
| AI 국면 2023~ | 54.54배 | -52.0% | 1.63 | 50건 | 66.0% | 33.18배 | 14.26배 (11.42) | 4.86배 (4.09) |
| 최근 5년 | 17.07배 | -82.4% | 1.09 | 73건 | 57.5% | 11.82배 | 3.32배 (2.89) | 3.79배 (3.26) |
| 전체 16.3년 | 103.44배 | -93.8% | 0.76 | 221건 | 57.9% | 38.94배 | **231.65배** (180.99) | 40.81배 (32.13) |

⚠️ **AI 국면(2023~)은 파라미터 탐색과 분류기 선택의 평가 구간으로 썼습니다.** 더 이상
"손대지 않은 구간"이 아니므로 54.54배를 out-of-sample 성과로 읽으면 안 됩니다.
검증구간 거래가 50건뿐이라 10~20% 차이는 구분할 수 없습니다.

✅ **백테스트와 실거래가 같은 판단 경로를 씁니다.** 둘 다 `strategy.decide_action()` 하나만
쓰고, 16.3년 4,088거래일 전부에서 같은 행동이 나오는 것을 `tests/test_consistency.py` 로
확인합니다. 위 표는 실제로 매매했을 때 기대하는 수치입니다(실 슬리피지는 별도).

예전에는 백테스트가 청산 당일 같은 가격에 재진입할 수 있고 알리미는 하루 늦어서, 같은
전략이 전체 기간 48배 vs 83배로 갈렸습니다. 아래 "목표 포지션" 설명 참고.

**최근 3년 기준으로는 우위가 분명합니다** — 세후 22.45배 vs SOXL 6.64배. 낙폭도
-52.0%로 SOXL 단독 보유(-88%대)보다 훨씬 얕습니다.

⚠️ 다만 **전체 16.3년으로 보면 SOXL을 그냥 들고 있는 편이 훨씬 낫습니다**(103배 vs 232배,
세후 39배 vs 181배). 기간을 길게 잡을수록 전략이 불리해지고 낙폭은 -93.8%까지 커집니다.
**학습구간(2010~2022) 13년만 보면 1.59배뿐**이고, 같은 기간 SOXL 매수보유는 15.44배였습니다
— 이 전략의 성과는 사실상 2023년 이후에서 나옵니다. 최근 3년이 좋아 보이는 것과 16년이
나쁜 것 중 어느 쪽이 미래를 대표하는지는 알 수 없습니다.

분류기에 가격 조건을 넣은 선택도 **최근 구간에 유리하고 장기에 불리한 방향**이었습니다
(최근 3년 +26%, 전체 -13%). 장기 견고성을 우선하려면 대안이 있습니다
([docs/STRATEGY.md](docs/STRATEGY.md) 3.1).

## 사용법

### 백테스트
```bash
./.venv/bin/python src/backtest.py                    # 최근 3년 (기본값)
./.venv/bin/python src/backtest.py --years 5          # 최근 5년
./.venv/bin/python src/backtest.py --since 2023-01-01 # AI 국면
./.venv/bin/python src/backtest.py --years 0          # 전체 기간
./.venv/bin/python src/backtest.py --exposure 0.5 --csv
```

### 매매 실행 (미국 정규장 개장 직후 실행)
```bash
./.venv/bin/python src/alerter.py                     # 오늘의 지시만 확인 (읽기 전용)
./.venv/bin/python src/alerter.py --execute           # 안전장치 검사 + 드라이런
./.venv/bin/python src/alerter.py --live --notify     # 실제 매매 + 텔레그램 보고
./.venv/bin/python src/alerter.py --slippage          # 신호가 대비 체결가 차이
```

**실행 시점은 미국 정규장 개장 직후입니다.** 전략 신호는 전 거래일 종가로 확정되고,
백테스트가 검증한 체결 시점이 다음 거래일 정규장 시가입니다.

1시간봉 2.9년(35건)으로 진입·청산 시각 **64개 조합**을 전부 재보니 **09:30 개장이
최고**였고 늦출수록 단조롭게 나빠졌습니다 — 09:30 30.9배 / 10:30 30.2배 / 11:30 27.3배 /
12:30 **16.2배** / 15:30 13.1배 / 종가 23.0배. 그래서 executor는:

- 개장 후 **30분 안**을 목표로 하고,
- 30~120분은 경고와 함께 진행하며,
- **120분이 지나면 주문하지 않고 그날을 건너뜁니다**(`--max-late`).

늦게 체결하는 것보다 거래를 포기하는 편이 낫다는 실측 결론입니다
([docs/STRATEGY.md](docs/STRATEGY.md) 7.1). 애프터장은 거래량이 정규장의 0.0%라 표시
가격에 살 수 없습니다(7장).

### 토스증권 API 설정

```bash
cp config/.env.example config/.env                    # TOSS_API_CLIENT_ID/SECRET 입력
./.venv/bin/python src/alerter.py --toss-accounts     # accountSeq 확인 후 .env에 입력
./.venv/bin/python src/alerter.py --execute           # 드라이런으로 연결·안전장치 확인
```

⚠️ **IP 허용 목록 등록이 먼저입니다.** 등록하지 않으면 토큰 발급이 막힙니다:

```
조회 실패: [403 access_denied] IP address not allowed
```

토스증권 개발자센터에서 실행할 장비의 **공개 IP**를 등록하십시오. 현재 IP는
`curl -s https://api.ipify.org` 로 확인합니다. 가정용 회선이면 IP가 바뀔 수 있으니
바뀔 때마다 재등록해야 합니다 — 무인 운전에서는 이게 조용한 실패 원인이 됩니다.

### 연결 점검 (최소 수량 주문)

전략과 무관하게 API 경로(토큰 → 계좌 헤더 → 주문 → 체결 조회)만 최소 수량으로 확인합니다.
journal에 포지션으로 기록되지 않고, 킬 스위치와 세션 확인은 그대로 적용됩니다.

```bash
# 정규장 (시장가)
./.venv/bin/python src/alerter.py --smoke-buy 1                          # 드라이런
./.venv/bin/python src/alerter.py --smoke-buy 1 --live                   # 실제 매수
./.venv/bin/python src/alerter.py --smoke-sell 1 --live                  # 정리

# 프리장 (지정가 — 유동성이 얇어 시장가를 쓰지 않습니다)
./.venv/bin/python src/alerter.py --smoke-sell 1 --smoke-session pre --live
./.venv/bin/python src/alerter.py --smoke-sell 1 --smoke-session pre --smoke-limit 35.20 --live
```

프리장은 `--smoke-limit` 을 생략하면 **현재가 대비 1% 양보**한 지정가를 자동 계산합니다
(매도는 -1%, 매수는 +1%). 미체결분은 세션 종료 시 자동 취소됩니다.

실측 예 (2026-09-22 프리장): 지정가 $35.31로 낸 SOXS 1주 매도가 **$35.66에 체결**됐습니다
(지정가보다 유리). 수수료·세금 $0.04.

⚠️ 매수한 주식은 계좌에 남고, 그 상태로는 전략의 신규 매수가 잔고 대조에서 막힙니다
(`이미 SOXS 1주를 보유 중입니다`). 점검이 끝나면 `--smoke-sell` 로 정리하십시오.

⚠️ **전략 실행 경로는 프리장을 허용하지 않습니다.** `run_execution` 은 정규장 개장 후
120분만 허용합니다(7.1 실측 근거). 프리장 지원은 이 점검 경로 전용입니다.

### 무인 자동매매 (cron)

`scripts/daily_trade.sh` 가 알리미를 `--live --notify` 로 돌리고 `journal/logs/YYYY-MM.log`
에 기록합니다. **여러 번 실행돼도 주문은 개장 직후 한 번만 나갑니다** — executor가 개장 후
120분이 지나면 거부하고, 멱등성 키(신호일+액션+종목)로 중복을 막습니다.

```bash
# 설치 (직접 실행하십시오. 저장소는 crontab을 건드리지 않습니다)
crontab -e
# 아래 한 줄 추가
*/15 22,23,0,1 * * 1-6 /path/to/new-soxl-soxs-bot/scripts/daily_trade.sh
```

15분마다 두드리는 이유는 **서머타임**입니다. 개장은 KST 22:30(서머타임) / 23:30(표준시)로
한 시간 밀리는데, 넉넉한 창을 반복 실행하고 멱등성으로 중복을 막는 방식이 시각을
계절마다 고쳐 넣는 것보다 안전합니다.

```bash
touch config/HALT     # 즉시 중단 — 어떤 주문도 나가지 않습니다
rm config/HALT        # 해제
./scripts/daily_trade.sh --execute   # 드라이런으로 점검
tail -f journal/logs/$(date +%Y-%m).log
```

### 대시보드 (조회 전용)

현재 레짐·가격, 봇 주문내역, 성과를 3개 탭으로 봅니다. 주문·청산 기능은 없습니다.

```bash
./.venv/bin/python scripts/build_dashboard.py   # 데이터 + results/dashboard.html 생성
open results/dashboard.html                     # 로컬에서 보기 (1분마다 자동 새로고침)
```

**1시간마다 자동 갱신** — `scripts/refresh_dashboard.sh` 를 cron에 넣습니다.

```bash
crontab -e
0 * * * * /path/to/new-soxl-soxs-bot/scripts/refresh_dashboard.sh
```

⚠️ **자동 갱신되는 것은 로컬 `results/dashboard.html` 뿐입니다.** claude.ai에 발행한
페이지는 데이터가 발행 시점에 고정됩니다. 발행 페이지는 보안 정책(CSP)상 외부로
요청을 보낼 수 없고, 런타임 기능 중 로컬 프로세스가 페이지에 데이터를 밀어넣을 수 있는
것도 없습니다. 휴대폰에서 최신을 보려면 Claude에게 재발행을 요청해야 합니다.

두 경우 모두 상단에 **"데이터 N분 전"** 배지가 나이를 보여줍니다(70분 넘으면 주황,
4시간 넘으면 빨강). 스냅샷을 실시간으로 오해하지 않도록 넣었습니다.

주문내역은 **봇이 낸 주문만** 나옵니다. 토스 주문 목록 API가 `clientOrderId` 를 돌려주지
않아 증권사 내역만으로는 수동 주문과 구분할 수 없으므로, journal에 기록된 주문번호를
기준으로 삼고 증권사 상세를 덧붙입니다.

토큰은 `config/.env`에만 두며 `.gitignore` 대상입니다. 소스에 넣지 마십시오.

**안전장치** — 아래를 모두 통과해야 주문이 나갑니다:
킬 스위치(`config/HALT`) / **개장 후 120분 안** / journal과 증권사 잔고 대조 /
1회 금액 상한 / 24시간 주문 건수 상한 / clientOrderId 멱등성(재실행 시 중복 주문 방지).

**입력 안전장치** — 전략은 "일봉 종가"로 판단하는데 주문을 내는 시간(정규장 중)에는
당일 봉이 미완성입니다. `data_fetcher.drop_incomplete_bar()` 가 **미완성 당일 봉을
잘라내** 항상 완성된 종가만 쓰게 합니다. 이 가드가 없으면 장중 가격을 종가로 착각합니다.

**목표 포지션 모델** — 매 거래일 목표 포지션을 정하고 현재 포지션과의 차이만 행동으로
만듭니다. 그래서 백테스트와 실거래가 갈라질 여지가 없습니다.

| 목표 vs 현재 | 행동 | 주문 |
|---|---|---|
| 같음 | `HOLD` | 없음 |
| 목표 없음 / 현재 있음 | `CLOSE` | 매도 1건 |
| 목표 있음 / 현재 없음 | `OPEN` | 매수 1건 |
| 방향이 다름 | `SWITCH` | **같은 장에서 매도 → 매수** |

청산 조건이 걸렸는데 **같은 방향으로 다시 잡을 상황**이면 팔고 되사지 않고 규칙만
갱신합니다(`RESTAMP`). 예전에는 같은 가격에 되사면서 왕복 0.2%를 냈고, 전체 기간
106회 누적 약 19%가 아무 대가 없이 빠져나갔습니다. 거래 건수가 287건 → 181건으로
줄어든 것이 주로 이 때문입니다. `SWITCH`는 16.3년에 19번뿐입니다.

`.venv`는 `../soxl-soxs-bot/.venv`를 심볼릭 링크로 공유합니다.
